# JARVIS OS - Long Term Memory Architecture

This document describes the Long-Term Personal Knowledge System used by JARVIS.

## Architecture Overview

JARVIS uses a multi-tiered memory architecture consisting of:
1. **Context Manager**: Handles short-term context, reference resolution, and determines if a piece of information should be committed to long-term memory.
2. **Unified Memory API**: Orchestrates storage across three backends:
   - **SQLite**: Structured relational records (runtime sessions, project states).
   - **ChromaDB**: Semantic vector retrieval (high-performance semantic search).
   - **Markdown Vault**: Human-readable Obsidian notes (reports, wiki, project knowledge).

## Memory Categories
- **Temporary Memory**: Short-lived context (e.g., current conversation). Not saved to permanent storage.
- **Long-Term Knowledge**: Important information that remains useful (e.g., architectural decisions).
- **Project Memory**: Knowledge associated with a specific project (e.g., `jarvis-os`).
- **User Preferences**: Preferred workflows, formatting, etc.
- **Learned Knowledge**: Summaries, research findings generated by JARVIS.

## Memory Importance System
Memories are tagged with an importance level:
- `LOW`
- `MEDIUM`
- `HIGH`
- `CRITICAL`

## Memory Retrieval Strategy
Context Builder (`context_builder.py`) retrieves context by:
- Querying ChromaDB for semantic relevance.
- Filtering out expired memories (using `expires_at` metadata).
- Prioritizing memories based on importance score (`CRITICAL` = +3, `HIGH` = +2, `MEDIUM` = +1).
- Prioritizing memories matching the current active `project_id` (+5 score).

## Privacy
Privacy levels are strictly enforced via the `PrivacyLevel` enum:
- `LOCAL_ONLY`: Never sent to cloud APIs. Stored strictly in local SQLite/Vault.
- `PREFER_LOCAL`: Uses local models when possible.
- `CLOUD_ALLOWED`: Safe to send as context to cloud LLMs.

Sensitive environment secrets (API keys, tokens) are filtered by the `PrivacyBoundary` before reaching the memory storage layers.

## Explicit Memory Commands
Users can manage memory explicitly using the Memory Skill:
- "Remember that [fact]"
- "Forget that [fact]"
- "What do you know about [topic]?"

## Expiry and Consolidation
Memories can be assigned an `expiry_seconds` metadata tag. Expired memories are filtered out during retrieval. The Memory API provides a `consolidate_memories` method to periodically prune expired or superseded data.
